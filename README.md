# 箱装辣白菜

**服务器插件 1.0.0**，为[箱装辣白菜前端扩展](https://github.com/Yuyayun/boxed-lllllabc)提供可选的服务器存储（SQLite）。前后端分仓库，分别安装与更新。

> 本分支 `gpt/1.0.1-migration` 是尚未发布的 1.0.1 开发代码，下表协议/结构指本分支。需要配套同分支前端，不能与正式版 1.0.0 混用。完整开发状态和未完成验收见 [迁移工作记录](docs/acceptance/1.0.1-migration-worklog.md)。不要用开发代码覆盖真实备份进行试验。

只安装前端即可使用 IndexedDB。本插件只管理箱装备份数据库，不代替酒馆保存聊天；安装、启用或检查插件不会自动切换备份位置、迁移数据、同步或双写。

## 运行条件

| 项目 | 条件 |
|---|---|
| 配套前端 | 箱装辣白菜 **1.0.1 开发分支**，存储协议 **6**、分批迁移能力 **3** |
| Node.js | **22.14.0 或以上**，须有内置 `node:sqlite`；已验证 22.14.0、24.15.0 |
| SillyTavern | 已验证 **1.15.0、1.19.0** 的插件、用户身份、会话和 CSRF 接口 |
| 账户 | 关闭账户系统的默认用户，或登录身份与会话一致的唯一启用账户 |
| 数据库 | SQLite schema **4**，兼容原 schema 3，专用目录，服务器进程可读写且有足够空间 |

多个启用账户、身份无法可靠核实、关闭 CSRF 或跨源请求时拒绝操作。不提供多用户共享、跨设备同步或独立账户体系。Node 22 的 SQLite 模块仍可能显示实验性提示；其他版本需要核对兼容性。

## 安装

停止酒馆，在酒馆根目录执行：

```sh
git clone --branch main https://github.com/Yuyayun/boxed-lllllabc-server.git plugins/boxed-lllllabc-server
```

在酒馆 `config.yaml` 中将已有选项设为：

```yaml
enableServerPlugins: true
```

确认实际启动酒馆的 Node 版本符合要求，然后重启。在前端设置点击“检查服务器连接”，确认连接及读写状态；需要使用 SQLite 时，再点击“切换备份位置”并确认覆盖范围。

本插件没有额外的 npm 安装依赖，不另启 Node 服务，也不要求填写 URL/API Key。安装到 `plugins/boxed-lllllabc-server`，不要放进前端扩展目录 `public/scripts/extensions/third-party`。

## 配置数据库目录

默认使用酒馆数据根目录的同级 `boxed-lllllabc-storage` 文件夹。数据根目录为 `SillyTavern/data` 时，文件为 `SillyTavern/boxed-lllllabc-storage/boxed-lllllabc.sqlite`。

可在服务器 `config.yaml` 指定专用绝对目录：

```yaml
boxedLllllabc:
  databaseDirectory: /srv/boxed-lllllabc-storage
```

Windows 可使用 `databaseDirectory: 'C:/SillyTavern/boxed-lllllabc-storage'`。目录不能位于原生数据、`public`、`plugins` 或 `node_modules` 内，也不能是文件系统根目录或酒馆根目录本身。浏览器不能提交路径。首次成功请求绑定可信账户归属；不符时保留旧库并拒绝访问，不自动转交数据。

## 在前端使用

四类普通备份、快照、预览恢复、目录和清理均在前端操作，只使用当前选择的一个备份位置。

- **切换备份位置**：停止生成并关闭其他酒馆页签。新位置已有的箱装备份会被完整覆盖、不合并；复制和校验完成后才切换，成功后原位置备份仍保留。切回浏览器同样需要确认和校验。
- **清空原位置的备份**：仅成功切换后可操作已确认的原位置，需单独确认，包含普通备份、未保存变更和快照；不影响当前位置或酒馆聊天文件。
- **聊天快照**：独立分批保存、完整后发布并校验；重命名不改内容，未完成存档不能恢复。普通清理不删除快照。
- **批量清理**：事务内重核范围和预览，保留未保存变更及暂停更新/待确认完整备份；过期计划拒绝，中途失败整批回滚。
- **空间统计**：备份内容估算、数据库及 WAL/SHM 占用、服务器磁盘可用空间分别展示，不使用浏览器配额充当服务器空间。

恢复酒馆聊天文件由前端调用酒馆原生显示、保存及核对流程，本插件只负责箱装数据的存储。

## 故障与中断恢复

插件不可用、只读或协议不兼容时明确报错，不会擅自回退写入 IndexedDB。超时或网络中断可能使结果未知；先刷新核对实际数据，再重新预览，不要直接重试旧清理计划。

切换使用持久记录和提交回执。刷新/重启后先由用户确认恢复；完整来源清单及逐批内容复核通过后可续搬，来源变化或清点未完成时安全撤销并保留来源和目标原正式备份，已激活的切换只完成收尾。失联时保留记录并暂停。不要手动删除锁、暂存记录或浏览器控制库。

数据库带应用标识和版本，未知应用或未来版本不会被覆盖为空库。启动按页检查实际记录、主键与聊天归属并反馈进度，发现不能读取或解析的数据时停止开放操作，保留现场；这项逻辑检查不等同于 SQLite 整库物理 `quick_check`，后者不再是每次启动的长调用。删除记录后可能保留空闲页或 WAL，文件不立即缩小不代表删除失败。

早于 schema 3 的数据库先生成同目录 `.before-v3-*.bak` 一致逻辑备份（包含 WAL 中已提交内容），按页写入并读回核对；备份完成后才分批转换新结构。转换期间有持久登记与数据库触发器写入保护；中断后可继续转换，启用新结构后分批清理旧表。备份缺失、变动或检查点不完整时停止，不猜测进度。备份生成阶段中断会保留 `.bak.pending` 诊断文件，原库不进入转换；下次重新生成备份。不要手动删改升级登记、保护触发器、保留表或备份文件。

1.0.0 旧任务也按页恢复：未激活时清点回滚副本、分批恢复并完整读回核验，再清理暂存；已激活时按原任务逐键核验正式内容并复核总量，只收尾，不误回滚。来源记录不参与删除。旧任务的恢复检查点损坏或内容不符时保留锁和副本等待核对。

## 更新、停用与卸载

更新前停止酒馆，并备份专用目录中的 `.sqlite` 及仍存在的 `-wal`、`-shm` 文件；不要仅在线复制主文件充当一致备份。在插件目录执行 `git pull --ff-only`，再重启酒馆。

本开发分支前后端均需协议 **6**、分批能力 **3**。正式 **1.0.0** 仍使用协议 **5**，应配套安装，不与本分支混用。使用 IndexedDB 不要求安装本插件。存在未完成任务时不要直接切回旧版本，先用配套版本完成恢复与收尾。

停用服务器插件，或停止酒馆后移除安装目录，**不会删除专用数据库**。重新安装兼容版本可读原数据；已选择服务器存储时，停用期间会报告不可用，不自动切换位置。

## 实现与使用上限

使用 Node 内置 SQLite，在酒馆同进程工作线程中串行执行；有事务、WAL/FULL 同步、有界队列。接口沿用原生同源、登录态和 CSRF，只接受白名单业务操作，不提供任意 SQL 或文件路径入口。

- 同源路由：`/api/plugins/boxed-lllllabc/status`、`/operation`、`/batch-transfer`、`/logs`、`/logs/event`、`/logs/cleanup`。旧 `/transfer` 仅供已有任务恢复。
- 单请求 **16 MiB**、单记录 **8 MiB**；普通整包读取和响应预算 **32 MiB**，最多 **25,000 行**。
- 大目录返回逐聊天紧凑摘要；摘要及批量事务按聊天/类型读取时，每次预算 **128 MiB / 25,000 条**。
- 切换每页最多 **100 条 / 约 2 MiB**，较大单条独占一页，仍受单记录限制。
- 队列最多 **32**，写锁忙等待约 **1 秒**。工作线程以真实工作反馈判断长时间无进展（默认约 120 秒），心跳单独用于判断存活；请求等待超时不会自动杀死整个线程。前端按响应流是否持续到达判断连接超时，持续有反馈的任务不再受固定 15 秒总时长限制。

### 运行日志（1.0.1 开发功能）

日志写在 `boxed-lllllabc.sqlite` 同目录，文件为 `boxed-lllllabc-log-*.jsonl`，单段约 **2 MiB** 后轮换；小型 `.meta.json` 文件只索引保留期，不代替迁移登记簿。按迁移、日常、异常分类；日常成功操作按时间汇总，迁移记录阶段、方向、任务、清点/核验数量与安全错误代码，不记录聊天内容、参数载荷或密钥。

正常结束任务保留约 **7 天**，异常或恢复过的任务保留约 **30 天**，整个任务上下文一起保留；未结束任务不按年龄删除。后台每分钟分批检查保留期。前端入口支持筛选、分页、复制与确认后清理已结束日志。单页最多 100 条、读取预算最大 128 KiB，前端使用 50 条/默认 64 KiB；清理只处理日志，不删除数据库或任务登记。

容量查询改用随原事务更新的各类记录计数；已有数据库首次建立计数时按 100 条分页并汇报，完成前不把未知容量显示为零。迁移预检为新数据区、索引和 WAL 留出保守余量，不再次将已占用的整个目标库大小作为额外可用空间要求；预检不能保证之后磁盘一定充足，实际写入仍由事务保护。本分支的大数据和 Termux 验收尚未完成。

超限明确拒绝，不截断数据后继续删除。软件验收不等于任意规模、所有浏览器和所有版本均已验证，也不代表零性能影响。
