# 箱装辣白菜 · 服务器插件

为[箱装辣白菜前端扩展](https://github.com/Yuyayun/boxed-lllllabc)提供可选的服务器备份存储（SQLite）。前后端分仓库、分别安装。

**本分支为 1.0.1-dev.1 开发验收版，尚未正式发布。** 本机测试已完成，Termux 实机验收待使用者完成。请与前端 `gpt/1.0.1-migration` 分支配套使用；main 仍为正式 1.0.0，不与本测试版混用。

只安装前端即可使用浏览器本地备份。安装本插件后，不会自动切换位置或迁移数据；需要使用服务器存储时，再到前端确认切换。

## 运行条件

- Node.js **22.14.0 或以上**，且提供内置 `node:sqlite`。已在 22.14.0、24.15.0 检查；实验性 SQLite 提示本身不算错误。
- SillyTavern 的服务器插件功能已开启。本机已检查 1.15.0、1.19.0。
- 使用默认用户，或只启用一个账户并正常登录；当前不提供多用户共享备份。
- 保留酒馆默认的请求保护，服务器备份目录可读写，并留有迁移所需空间。

插件没有额外的 npm 安装步骤，不需要另外启动服务、填写服务器 URL 或 API Key。

## 安装

先停止测试酒馆。使用配套测试包时，解压后的目录应为：

```text
plugins/boxed-lllllabc-server
```

也可以在酒馆根目录使用 Git 安装当前测试分支：

```sh
git clone --branch gpt/1.0.1-migration https://github.com/Yuyayun/boxed-lllllabc-server.git plugins/boxed-lllllabc-server
```

在酒馆 `config.yaml` 中开启：

```yaml
enableServerPlugins: true
```

启动酒馆后，在前端设置点击“检查服务器连接”。确认连接正常后，当前备份位置仍不会改变；要使用服务器存储，需另外点击“切换备份位置”并确认覆盖范围。

后端不要放进前端的 `third-party` 扩展目录。保留旧代码时，将旧目录移到 `plugins` 之外，避免同时加载两份服务器插件。

## 备份放在哪里

默认使用酒馆数据目录同级的 `boxed-lllllabc-storage` 文件夹。例如数据目录为 `SillyTavern/data` 时，数据库为：

```text
SillyTavern/boxed-lllllabc-storage/boxed-lllllabc.sqlite
```

如需自定义，可在 `config.yaml` 指定专用的绝对路径：

```yaml
boxedLllllabc:
  databaseDirectory: /srv/boxed-lllllabc-storage
```

Windows 示例：`databaseDirectory: 'C:/SillyTavern/boxed-lllllabc-storage'`。

不要将其放进酒馆原生数据目录、`public`、`plugins`、`node_modules`，也不要直接使用磁盘或酒馆根目录。目录由服务器配置，浏览器不能自行指定。数据库首次使用后会记住所属账户，不会自动交给另一个账户。

## 与前端配合使用

普通备份、聊天快照、查看、恢复和清理都在前端操作。本插件只负责存储箱装备份，恢复聊天时仍使用酒馆自身的显示和保存流程。

- **切换备份位置**：分批搬运并核对，全部检查通过后才启用新位置。新位置已有的箱装备份会被覆盖，不会合并；成功后原位置副本仍保留。
- **原位置清空**：成功切换后才能单独确认清空旧副本，不影响当前位置或酒馆聊天文件。
- **快照**：独立留存，普通清理不会删除；恢复前需要预览和确认。
- **普通批量清理**：先预览再确认，保留未保存变更及受保护的完整备份；内容变化后需要重新预览。

两个位置不会自动同步或双写。服务器备份也不提供多个用户之间的共享和协调功能。

## 迁移较慢或中断时

前端会显示当前阶段、已经核对的数量和等待情况。存活反馈只说明服务还在处理，不能当作迁移已经完成。

可以请求暂停，等待当前步骤结束。页面关闭或酒馆重启后，需要明确确认恢复；内容一致时继续，无法确认时安全撤销并保留原数据。已经切换成功的任务只继续收尾。

失联时保留任务，不自动改写到浏览器。恢复连接后先核对，不要直接重试旧清理计划，也不要手动删除锁、临时数据或浏览器控制记录。

旧版本数据会先检查，再按需要分批升级。较早版本的数据库升级会额外保留同目录 `.bak` 备份；中断或检查不通过时保留现场，不覆盖成空库。大库准备需要时间，可根据阶段反馈判断是否仍在推进。

## 查看与清理日志

运行日志与数据库放在同一备份目录。前端的“查看运行日志”默认折叠，可按异常、迁移、日常或全部筛选，分页面读取并复制当前页。

日志记录发生了什么、处理到哪里和出错情况，不记录聊天正文、完整备份、密钥或令牌。重启后仍可读取，终端清屏不会影响任务恢复。

正常结束的任务约保留 7 天，出错或恢复过的任务约保留 30 天。未结束任务不按年龄自动删除。手动清理只处理已结束日志，不删除备份或恢复任务所需记录。

## 更新、停用与卸载

更新前停止酒馆，并保留备份目录，包括仍存在的 `-wal`、`-shm` 文件。不要把运行中单独复制的 `.sqlite` 主文件当作完整备份。

Git 安装可在插件目录执行 `git pull --ff-only` 更新当前分支；ZIP 安装则替换代码目录。前端同时使用配套版本。存在未完成任务时，先恢复或完成收尾，再考虑更换版本。

停用或卸载插件不会自动删除独立的备份目录。当前选中服务器存储时，停用期间会提示不可用，不会悄悄换到浏览器。删除记录后，数据库文件可能不会立即缩小。
