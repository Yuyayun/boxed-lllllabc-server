# 运行日志可读性补充（1.0.3 开发分支）

为所有开放的备份操作和存储任务步骤补充中文名称。worker 与路由保留具体操作、已知备份类型、处理阶段和排队时间；已记录的同一次异常不再重复记为通用“备份请求”。校验失败及未进入 worker 的异常仍记录；日志失败不能改变存储结果，缺少记录器时由路由补记。

分批暂存、正式提交、步骤完成和整项任务完成分别说明。按实际写入回执展示状态；已提交后再请求撤销，不显示成撤销成功。读取取消、写入取消、结果未知、版本变化、权限及 SQLite 锁定/只读/空间错误分别给出处理指引，不把请求结束当成酒馆聊天已保存。

30 个共享模块与配套前端逐字节同步；服务器终端通过格式化参数继续选择 UTC，浏览器沿用设备本地时间，不再维护两份文案实现。新日志字段仅接收固定类型、结果枚举、安全阶段标识及数字，不记录聊天正文、SQL、密钥或任意错误原文；前端上报接口不开放这些内部字段。

后端串行 150/150、前端 352/352、真实 SQLite 安全专项 19/19 通过；真实 HTTP 覆盖一次异常只记录一次、分批备份类型保留、非法内容不写日志、欢迎页取消与重新连接、日志实际写入失败不影响备份。详细配套验收见前端 `docs/acceptance/2026-11-20-top-panel-and-runtime-logs.md`。

协议、SQLite schema 及 1.0.3 版本不变，继续使用 `codex/1.0.3-backup-race`；没有访问真实聊天或备份库。本次未更改数据库写入、取消或结果确认规则。
