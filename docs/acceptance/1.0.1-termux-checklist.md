# 1.0.1 开发版：Termux 实机验收

状态：**交由使用者实机执行，尚未通过，也不是正式发布包。** 桌面测试结果另见 `1.0.1-desktop-acceptance.md`。

## 安装这一组测试包

- 前端：`boxed-lllllabc-1.0.1-dev.zip`，解压后目录放到测试酒馆 `public/scripts/extensions/third-party/boxed-lllllabc`。
- 可选后端：`boxed-lllllabc-server-1.0.1-dev.zip`，目录放到测试酒馆 `plugins/boxed-lllllabc-server`。服务器配置 `enableServerPlugins: true` 后重启酒馆。
- 两个包的 `BUILD-INFO.json` 标明提交及协议，按同一组配对。界面和配套插件版本均为 `1.0.1-dev.1`，表示尚未正式发布的 1.0.1 验收代码；不要与 GitHub main 的正式 1.0.0 混用。测试期间不要通过更新入口切回旧代码，存在未结束任务时也不要降级。
- SQLite 后端要求 Node **22.14.0 或以上**且有内置 `node:sqlite`。先记录 `node --version`；实验性 SQLite 提示本身不算失败。前端单独使用 IndexedDB 不要求安装 SQLite 插件。

只在测试环境安装。停止酒馆后保留原安装目录及服务器备份目录（包括仍存在的 WAL/SHM），再覆盖测试代码；不要把运行中单独复制的 `.sqlite` 文件当作一致备份。浏览器的站点数据要保留，清缓存或删除 IndexedDB 不是重置迁移任务的方式。

## 先记三项

1. Android、浏览器、Node、SillyTavern 的版本；是否使用这组配对代码。
2. 当前备份位置、记录/聊天/快照数量、约占空间、服务器剩余空间。
3. 任取几份普通备份和快照，记下可识别的内容，方便迁移后核对。不需要提供聊天正文或数据库给开发者。

## 建议按这个顺序验收

### 1. 前端独立工作

使用从未连接后端的测试浏览器环境，关闭服务器插件。普通备份、查看、快照、恢复应正常使用 IndexedDB；运行日志入口隐藏。检查连接不能自动换位置或发起迁移。

### 2. 安装后端，只检查连接

启用配套后端并检查连接。当前位置仍应是 IndexedDB，数据不会自动迁往 SQLite。“查看运行日志”出现且默认折叠，能筛选并复制当前页。

### 3. 用原来的约 4,551 条 / 479.2 MB 规模做一次往返

停止生成，关闭其他酒馆页签，确认目标已有备份可以被覆盖，然后明确开始切换。按界面区分“清点”“搬运并核验”“最终核对”“收尾”；仅有存活反馈不能算完成，只有明确成功后才算切换完成。

完成 IndexedDB → SQLite 后，核对数量、选中的普通备份和快照；试一次正常备份及预览恢复。原 IndexedDB 备份应仍保留。再从 SQLite → IndexedDB 做同样检查。记录两次耗时和最慢阶段即可，不拿桌面耗时当作手机必须达到的速度。

手机空间不足时记录拒绝结果即可，不必为验收额外填满磁盘。1 GB 以上属于额外规模项，设备条件允许时再做。

### 4. 暂停与重新打开

在已经开始搬运、来源清单已完整登记后，点击“暂停任务”，等待当前步骤结束，再刷新或重新打开页面。正常备份操作应保持锁定，需要明确选择“继续核对并恢复”；应核对已有批次后继续，不重复报成功或擅自切到另一端。

**特殊情况：最初清点还没完成就关闭时，下次恢复可能安全撤销任务。** 因为未读来源没有完整基线，这是当前设计的预期行为；两端原数据应保留，随后可以重新发起。

### 5. 服务器/Termux 重启

分别在搬运、最终核对或收尾阶段，尝试停止测试酒馆进程，再重新启动；浏览器也可以关闭后重开。恢复应依靠持久登记，不依赖过去的终端输出。不要手动删除锁、WAL、暂存表或控制记录。

如果新位置尚未启用，可以明确放弃任务，核对来源和目标原来的备份仍在；如果已经启用，则应继续收尾，不能误回滚。桌面故障注入已覆盖很短的提交窗口，手机不必靠手动操作精确命中毫秒级窗口。

### 6. 日志与断线

清空终端显示后，前端仍应能读取服务器运行日志。停止服务器时，曾连接过的日志入口保留并提示无法读取；恢复服务后可以再读。

尝试筛选、翻页、复制。确认清理已结束日志后，未结束/待恢复任务的日志和正式登记仍须保留。正常任务约保留 7 天；异常或恢复过的任务约 30 天，未结束任务不按年龄自动删除。保留期不需要在一天内全部验证。
