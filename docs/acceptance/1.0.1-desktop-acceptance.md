日期：2026-10-29。前后端配套版本 `1.0.1-dev.1`，开发分支均为 `gpt/1.0.1-migration`。**本机验收完成；Termux 实机由使用者负责，尚未记为通过。** 按授权推送开发分支，不合并 main、不创建正式 Release。

本记录补充[分阶段工作记录](1.0.1-migration-worklog.md)，不改写此前各轮当时状态。唯一需求依据为使用者提供的 1.0.1 文档，原文不提交。没有新增同步、多用户支持或改变普通备份规则。

- 配套能力：协议 6、分批迁移 3、恢复 1、控制库 2、IndexedDB 8、SQLite 4。只有双方能力一致才启用新版迁移；只装前端仍可正常使用 IndexedDB。

## 大数据往返与独立核对

真实 1.15.0 / Node 22.14.0，每组 175 段聊天、4,551 条记录：聊天索引 175、最近 875、未保存变更 175、完整 2,800、历史 350、快照 44、快照消息 132。使用不易压缩的随机正文，保留候选、日期及 undefined 等编码，独立逐键摘要核对来源和目标，不在最终提交时读取整库到内存。

| 规模 | 实际编码字节 | IndexedDB → SQLite | SQLite → IndexedDB | 启用步骤耗时（SQLite / IndexedDB） | 进程重启后再核对 |
|---|---:|---:|---:|---:|---:|
| 正文约 479.2 MiB | 504,886,442 | 142.9 秒 | 161.4 秒 | 6.8 / 5.7 毫秒 | 通过，13.8 秒 |
| 正文 1 GiB | 1,076,147,282 | 306.4 秒 | 327.4 秒 | 4.5 / 3.0 毫秒 | 通过，31.2 秒 |

时间包含清点、搬运、反复核验及收尾，不是单纯传输速度。成功后两端逐键内容和快照均一致，原位置内容保留，当前端可正常读写。1 GiB 场景 SQLite 每批最多 100 条、2,026,272 字节，543 次追加；启用参数仅 743 字节，未在最后再复制整库。

另在 1 GiB 来源完整登记、已核验 503 条时中断，**真实终止并重启宿主进程**。目标事先加入不同的旧数据标记；明确放弃后，来源及原目标均完整保留，独立摘要与快照核对通过。测试结束恢复标记并再核对原内容。该测试是受控步骤边界加进程终止，不代表操作系统断电或精确中断 fsync。

## 资源观测与空间不足

| 指标 | 479 MiB 组 | 1 GiB 组 |
|---|---:|---:|
| 宿主工作集最大采样 | 636.8 MiB | 621.7 MiB |
| 系统报告宿主进程生命周期峰值 | 1,166.1 MiB | 1,144.7 MiB |
| 浏览器进程组工作集最大采样 | 1,171.4 MiB | 1,055.9 MiB |
| 当前页面 JS 堆最大采样 | 80.8 MiB | 78.7 MiB |
| 数据库、WAL、SHM 合计最大采样 | 490.5 MiB | 1,040.5 MiB |
| 同时读取宿主首页最大延迟 | 40.3 毫秒 | 61.8 毫秒 |

观测约每 2 秒一次，工作集约每隔一次采样读取；这些是整个宿主/浏览器的观测值，包含宿主自带功能、共享映射等，不能当作插件独占内存或手机资源上限。文件峰值也是采样值，不能据此降低容量预留或保证所有设备的磁盘峰值。

- 后端用真实 SQLite `max_page_count` 触发 `SQLITE_FULL`：当前批次记录及回执回滚，来源、不同的原目标均保留，可明确放弃并重新读取。没有填满用户实际磁盘。
- 真实 1.19.0 中注入不足的浏览器空间估算，迁移预检拒绝；确认放弃后两端原数据保留。
- 真实 IndexedDB 写事务第二次写入注入 `QuotaExceededError`，验证当前批次回滚、任务留存、明确放弃及两端独立内容一致；持久日志保留正确异常名称。**这是事务故障注入，不是实际耗尽浏览器配额。**
- Edge CDP 配额覆盖尝试未实际限制 IndexedDB，未计为有效配额测试。首次宿主准备遇到依赖目录联接及默认 Horde 联网行为，改为物理复制依赖和离线设置后重测通过；不把这些工具准备错误写成产品故障或验收通过。

## 旧版真实格式升级

从已发布 main 基线生成旧数据：前端 `66e1e0158ea233bbac3e6200956eb5546685c78a` 的原 IndexedDB 迁移/结构模块，后端 `555c26d4e36652da9bac2b8178f7094f3eaf6ffc` 的原 SQLite 仓储。不是用新版模块模拟旧结构。

以 4,551 条 / 504,886,442 字节在真实 1.19.0 打开：IndexedDB 7 → 8、控制库 1 → 2、SQLite 3 → 4 均通过。两端独立摘要与旧内容一致，头尾快照预览有效，新备用区为空、无未结束任务，当前仍为 IndexedDB。升级不自动迁移或切换存储。

更早 SQLite 结构、已提交 WAL、独立 `.bak`、恢复写保护和各阶段中断由第四轮真实文件/工作线程测试覆盖。启动分段逻辑检查不等同 SQLite 全物理完整性检查；数据库原生打开、WAL 恢复及刷盘仍有设备相关耗时。
